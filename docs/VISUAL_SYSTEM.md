## 1. コンセプト
白・墨色・薄灰の静かな紙面。かわいさは丸み、余白、細い線、猫の簡素な表情から生み出す。機能アイコンは意味が直感的な一般的ピクトグラムに統一し、猫はブランドと任意の反応のみ。ボタンをすべて猫の形にしない。グラデーション、ガラス効果、常時動く装飾、派手な色、音、強い影を禁止。学年・クラスの色バッジ以外は原則無彩色。Google公式ブランドを表示する場合は公式の例外規則に従い改変しない。

## 5. 猫マスコット
仮称 Desk Cat。モノクロ線画、丸みのある頭、三角耳、点の目、短い口、左右各2本のひげ、ゆるい尻尾。性別や衣装の設定なし。原型は既存WidgetSkin.Catのシルエットを継承。マスター64x64または80x64のベクター、頭部の位置/耳/足元は固定し、表情差分で跳ねない。時計右側で58〜76 DIP。ブランド/タスクバーのアプリアイコンは顔だけの簡略版、ICO 16/24/32/48/64/128/256を同一原型から生成。16ではひげ・尻尾等を省略可。透明背景、外部画像なし。
| Asset ID | 表情・動き | 条件 |
|---|---|---|
| cat-idle | 基本、点の目 | 既定 |
| cat-blink | 目が短い横線 | 任意の一回のまばたき、既定OFF |
| cat-happy | 目が弧、小さな尻尾の動き | タスク完了など成功後1回、装飾ON時 |
| cat-focus | 少し目を細める | 授業中、静止 |
| cat-rest | 目を閉じる | 本日の授業終了、静止 |
| cat-app | 簡略化した顔 | アプリアイコン |
追加案 cat-sync（小さな首傾げ）は優先外。猫でエラー、出欠、同期可否を単独表示しない。設定で猫非表示、動きなし（既定）/控えめを選択。常時ループ、追従アニメーション、音は禁止。OSのモーション削減設定では完全静止。授業終了や休憩中の自動アニメを既定で行わない。

## 6. マイクロインタラクション
動作の優先順位：即時の視覚反応 > データ処理の正確さ > 装飾。アニメーションは処理を待たせる演出にしない。
| 操作 | 挙動 | 時間・曲線 |
|---|---|---|
| hover | 背景/枠を薄灰に補間 | 100〜130ms ease-out |
| mouse/key down | 見た目のみ scale .98、Y +1 DIP、背景をPress | 60〜80ms ease-out |
| release | 元の位置・大きさ、hoverへ戻る | 110〜150ms ease-out |
| pointer離脱/取消 | 押下解除、クリックは実行しない | 100ms以内 |
| toggle | 選択色と輪郭を変える、状態を明示 | 120ms |
| checkbox | 成功保存後にチェックと取り消し線、短いopacity | 120〜150ms |
| 日付切替 | 内容を即更新、軽いfade (0.85→1) | 100〜150ms |
| ミニ/通常 | サイズを確定してから内部表示のみ短いfade、ドラッグ/サイズ変更を妨げない | 150〜180ms |
| 管理ダイアログ | OS標準を優先、内部のみ必要に応じfade | 120〜160ms |
| 同期/読み込み | 押下直後に処理中、必要時のみspinner、ボタン二重実行防止。成功時チェック/失敗時説明・再試行 | spinner約800〜1000ms/周、処理終了で必ず停止 |
| 猫の反応 | 一回の瞬きまたは尾の小変化 | 120〜220ms、最大500ms以内 |
同時進行は最小限。押したように見えるが実処理失敗なら完了表示しない。取消可能な処理は中止ボタン、長い処理は進捗不明でも状態表示。再クリックでアニメを積み重ねない。焦点を奪う・大きく揺れる・レイアウトを再測定する動きなし。OSのアニメ設定（SystemParameters.ClientAreaAnimation等）とアプリの「動きを減らす」を尊重し、縮小/移動/fadeを省略、即時状態変更のみ。最小化/非表示時は装飾アニメを停止。標準ボタンの押下/キーボード機能を保持。

## 7. WPF実装の方針
Themes/Tokens.xaml、Controls.xaml、Icons.xaml、CatAssets.xaml を候補にし、ResourceDictionary/ControlTemplate/VisualStateManager/Storyboardの共通部品とする。個々のButtonでテンプレートを複製しない。RenderTransform（Scale/Translate）と色・Opacityのみを短時間変更し、LayoutTransform/幅/高さ/Marginの連続アニメーションを避ける。ヒット領域は変えない。動作時だけ開始し完了後に時計・イベント購読を解放。画面描画/時計更新を必要な箇所だけ変更する。現WidgetSkinは毎分body全再生成、次授業ラベル全再生成を行うため、日付選択中のフォーカスや押下を壊し得る。時計と状態差分更新を分離し、再生成はデータ変更時のみ、選択/スクロール位置を保持。リサイズ中はアニメ省略。WPF標準の入力・AutomationPeer・OSファイル選択/印刷を維持。
参考: https://learn.microsoft.com/ja-jp/dotnet/desktop/wpf/controls/styles-templates-overview
https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/transforms-overview

## 8. Google Calendar認証UX
現状はOAuth JSON選択→本人確認→既定ブラウザGoogle認証という実装。要求は通常利用者がJSONを意識しない導線。設定画面を未連携/認証中/カレンダー選択/連携済/期限切れ/失敗の状態に分離。
未連携: 「Googleカレンダーと連携」→「Googleの認証ページをブラウザで開きます。予定の読み取りのみ許可します。名列・授業データ・タスクは送信しません」→「ブラウザで認証」。
登録済みの配布用Desktop OAuthクライアント構成が使用可能なら、ファイル選択を省いて認証へ。未設定の場合は開発者/管理者の初期構成が必須。評価版では詳細設定の「OAuth設定ファイルを読み込む」を維持し、未設定状態を明示。通常利用者にGoogle Cloud作成を毎回要求しない。正式配布用クライアントの登録、Googleの同意画面/検証・学校Workspace管理ポリシー、必要スコープ承認は別途確認する。アプリの公開Repoに認証情報・トークン・実設定JSONをコミットしない。デスクトップクライアント情報は秘密を維持できないクライアントである点を前提にGoogle公式仕様・規程と現AGENTSに沿った構成を決定する。登録済みアプリ情報を配布する方式とローカル設定方式の決定・承認前に偽のclient IDやブラウザで単にcalendar.google.comを開く処理で連携済扱いしない。
既存PKCE S256/state/loopback/システムブラウザ・DPAPI保護・最小Calendar読取scopeを継承。認証中は「ブラウザで許可を完了してください」・取消、成功後は選択カレンダーをチェックして「予定を取得」。失敗/取消時は既存連携とキャッシュを保全。Google Tasksや予定書込みは不可。既定OFF・手動同期を維持。ログインはアプリ自体の利用条件ではない。GoogleブランドのSign inボタンを採用する場合、公式ガイドの色/ロゴを改変しない。今回は一般的なカレンダー連携の文言と外部リンクアイコンを優先。
参照: https://developers.google.com/identity/protocols/oauth2/native-app
https://developers.google.com/identity/protocols/oauth2/resources/best-practices
https://developers.google.com/identity/branding-guidelines
