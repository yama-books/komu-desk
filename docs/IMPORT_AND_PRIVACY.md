# Excel移行・通信境界 詳細仕様 v0.1
公開可能な汎用仕様。元データ・実際の予定・クラス・名列・数値は保存しない。

## 1. Excel互換アダプタ
既存の授業数管理ワークブックの構造を確認した。年間予定の表、曜日×時限の時間割、日別展開表、集計、授業日一覧、名列、名列入力、進度記入用紙という8領域がある。実装では一般的な表形式とこの構造のプリセットを用意し、列位置をユーザー確認で確定する。生徒情報領域は既定で選択しない。
| 領域 | 入力/出力 | 移行方針 |
|---|---|---|
| 年間予定 | 入力 | 日付・タイトル、任意時刻・終了・メモ。行番号は元行参照用のみ。同日の複数予定を保持 |
| 時間割 | 入力 | 曜日列、時限行、空欄/ハイフンは空き。学年・クラス・科目をマッピング。特殊な曜日コードは休業/考査テンプレートに変換 |
| 日別展開 | 入力/出力 | 日付・曜日コード・各時限・考査区分。通常曜日との差を例外候補、保存済み表示値と計算式を区別。過去実績と計画の区別は本人確認 |
| 集計 | 照合/出力 | 基準日・期間全体・残数・欠席可能回数。数式を移植せず独立計算し差分表示 |
| 授業日一覧 | 照合/出力 | 回次・日付・時限を共通データから再生成 |
| 名列/入力 | 任意入力/出力 | 学年・組・番号・氏名を明示マップ。学籍番号は必要時のみ、文字列保持。名列は通常取り込みから分離 |
| 進度用紙 | 出力中心 | 回次・日付・記入欄。手書き内容の自動認識なし |

既存ファイルには日付照合の最初の一致、文字列COUNTIF、曜日コードの手入力、TODAYと補正値、考査日の検索、外部参照/名前定義が存在し得る。これらの実装依存は持ち込まない。デバッグ補正日を実績の根拠にしない。考査回数、出席境界、期間を確認する。旧版の授業日一覧と現行科目名が一致しない場合は候補を示し自動結合しない。

## 2. 取り込み画面と処理
1. ファイル選択（xlsx、CSV、ICS。xls/xlsmは初期対象外、xlsx保存し直しを案内）。ネットURL取得なし。
2. 読取専用で構造解析。zip展開量/件数/セル数の制限、パストラバーサル/外部エンティティ拒否。マクロ・外部接続・DDE・埋込オブジェクト・数式実行なし。数式セルは保存済みキャッシュが存在する場合のみ候補として表示、キャッシュなし/エラーは要確認。原本を上書きしない。
3. シートと列、日付、時限、年度、クラス/科目、特殊コードを対応付け。1900/1904日付体系・時刻小数・和暦/文字列の曖昧さを検出。ゼロ埋め名列番号を維持。文字列正規化はマッチ候補のみ、原表記を保全。
4. 取り込みプレビュー（追加/更新/重複候補/未解決/無視）、元セルへの参照と理由。名列領域は別途明示選択し、プレビューを常駐画面に出さない。
5. 確認後に単一トランザクションで反映。重大な未解決行は取り込まないか全体中止を選択。変更前のバックアップまたは差分履歴で取り消せる。同一ファイル・同一マップで再取り込みしても重複させない。
6. 集計照合画面で元キャッシュと新計算の差を表示。キャッシュは過去の計算結果であり正解とは限らない。本人の確認で確定。
行事の同日・同タイトルは異なる行なら別イベントの可能性。重複判定は元の安定ID/取り込み元・行識別と内容ハッシュを併用。異なるファイルやGoogleと同内容のイベントは統合候補であり自動削除しない。

## 3. Google Calendar読み取り専用
同期はOFFが既定。Calendar以外のネットワーク機能を提供しない。OAuthに必要な認証・トークン更新・API通信のみ例外。実装時にGoogle公式仕様を確認し、最小スコープ（calendar.readonly またはより狭い読み取りスコープの組合せ）、デスクトップOAuth/PKCE・localhost callback、OS資格情報保管を検討。アプリ内に共有秘密鍵を埋め込まず、ユーザーにシークレットを公開させない。Google Workspace管理者が拒否した場合はローカル/ICSモードに留まる。
- カレンダー選択、同期対象期間の明示、初回取得、ページング、差分同期（対応する同一クエリ条件でsyncToken）、無効トークン時の再取得、削除通知、繰り返し例外・終日イベントの排他的終了日を処理。
- 有限の年度範囲キャッシュを設計し、APIのsyncTokenと時間範囲フィルタの制約を実装時に確認する。必要なら選択範囲の限定再取得を採用し、過剰な全履歴取得を避ける。
- イベントIDとカレンダーIDで一意。繰り返しインスタンスはoriginalStartTime等を利用。再同期の同一イベントは更新として処理。複数日イベントは日別表示のみ展開し、原イベントは一件。
- 同期処理をUIから切り離し、同時実行を禁止、タイムアウト・指数バックオフ、最後の成功時刻・失敗/オフライン表示。既定15分、手動更新。取得対象をイベントID・日時・表示名等必要な項目に限定し、説明/参加者/添付は既定取得しない。
- ローカルタスク・授業・名列・出欠・進度に関するAPIは作らない。Google Tasksは含めない。同期OFF時はタイマー停止。キャッシュ削除と連携解除は本人操作。OAuth revokeは本人が明示的に選んだ場合のみ必要通信として扱う。
- Calendarデータは授業変更の候補を作るだけで、確定済み授業を上書きしない。Googleへのイベント作成/更新/削除を禁止。

## 4. 通信の実装境界
UIは同梱リソースのみ。WebViewを採用する場合はリモートナビゲーション、新規ウィンドウ、任意URL取得、外部画像/フォント、外部リンクの自動展開を禁止。CSPは初期deny、UIから外向きfetchを行わず、Calendar adapterのみが許可済みAPIホストに接続。IPCは入力スキーマを限定し任意パス/SQL/シェル/URLコマンドを提供しない。外部のHTTPライブラリにDB全体を渡さない。資格情報はWindowsの保護された保存機構へ。
- アプリ自体の通信とOS/WebView2/ブラウザ等の基盤通信を区別して実測し、必要なら採用技術を変更。完全ローカルの要件を満たせないランタイムを無条件採用しない。
- アプリ更新は手動配布、クラッシュレポート/テレメトリ/クラウドバックアップなし。開発時のGitHub/依存取得は実行時通信とは別。
- ローカルファイルの入出力は本人選択。ネットワーク共有/クラウド同期先を既定にせず、組織の管理規則に従う。OS暗号化/ACLを利用できるか確認し、SQLiteのみで暗号化済みと表現しない。
- 公開Repoに原本・データ・ログ・資格情報を入れない。gitignoreだけを安全性の保証としない。差分確認、合成fixture、秘密情報チェックを併用。

## 5. 出力・保全
印刷/Excel出力はローカルで生成。数式注入を防止（CSVやxlsxの入力文字列を式にしない）。印刷プレビューで名列含有を明示。PDF/Excelは本人の選択場所に出力。バックアップは一貫したDBスナップショット、形式版、整合性検証、復元前の現DB退避。資格情報を含めない。復元は別フォルダで先に検証し原DBを破壊しない。保持期間は設定でき、削除は確認を経る。

## 6. 受入
ネット切断で全主要機能、インポート/出力/復元/再起動が完結。ネット接続状態でもCalendar OFFならアプリ起因の外向き通信ゼロ、ONなら必要なCalendar/OAuth以外なしを観測。疑似サーバーと合成カレンダーで差分/削除/通信失敗/キャッシュを検証。Excelの同日複数予定、特殊コード、空欄、未保存数式結果、再取り込み、誤った列指定、取消を検証。実原本は許可されたPCでのみ照合し、公開記録には結果の一般的な合否のみ。
