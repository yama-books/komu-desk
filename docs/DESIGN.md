# KOMU DESK 基本設計 v0.1
2026-11-24 / 初期設計（実装・実機検証前）

## 1. 目的と範囲
教員のWindowsデスクトップに今日の予定・授業・次の授業・タスクを表示し、同じローカルデータで年間行事、授業数計上、授業日一覧、進度、帳票を管理する。既存Excel業務の移行を目指す。名列・出欠は任意の後続機能で、名列なしでも全ての時数集計を利用可能とする。

## 2. 確定した通信境界
完全ローカルを既定。唯一の通信例外は、本人が明示的に有効化したGoogle Calendarの読み取り同期と必要なGoogle OAuth。認証・APIの必要な宛先のみを許可し、実装時に公式仕様とネットワーク検証で確定する。Google Tasks連携・カレンダーへの書込み・独自バックエンド・CDN・外部フォント・テレメトリ・自動更新通信なし。タスクはローカル機能。
- Calendar adapterは選択したカレンダーのID、同期カーソル、認証情報と取得したイベントのみを扱う。名列・出欠・進度・タスク・学年クラス情報・帳票を送信しない。
- OAuthはシステムブラウザとデスクトップ向けフロー、最小読み取りスコープ、OS資格情報保存を候補とし、実装時に管理ポリシーとGoogleの公式仕様を確認する。
- 連携OFFなら自動通信しない。失敗時はキャッシュを表示し最終同期日時・古い情報であることを明示。手動更新と15分間隔を候補とし、バックオフを使用。Google側の削除・更新はローカルの元イベントに反映するが確定授業を自動変更しない。
- ローカルデータやバックアップは学校の承認済み保存先に限定し、クラウド同期フォルダを既定にしない。名列等の外部リンクを自動で開かない。ログに個人情報・認証情報を出さない。インポート、印刷、出力にもネット通信を追加しない。

## 3. UI
モノクロ、余白と読みやすい文字、色は学年・クラスの識別バッジ中心。色以外にもラベルを表示し、ライト/ダーク両方で可読性を確保。装飾の猫は任意・静止を既定。
- 今日：日付、時計、次の授業・開始までの時間、時限ごとの授業/空き、終日/時刻付き予定、ローカルタスク、更新状態。授業回数は任意表示。
- 通常ウィンドウ、最前面、ミニ表示、デスクトップ固定（Windows実機で可否確認）、トレイ、任意自動起動、位置・サイズ・文字サイズ・透明度を記憶。固定方式が不安定なら通常ウィンドウを優先。
- 管理：月間・年間カレンダー、週間時間割、時程、授業数、授業記録、タスク、帳票、設定。今日から対象日・授業詳細へ遷移。
- 学年、クラス、科目、授業グループを独立登録。任意名称・色・学年横断/合同/選択授業に対応。色変更はIDや履歴に影響しない。画面に生徒氏名を常駐表示しない。

## 4. 年度・時間割・行事
年度の開始終了、学期、考査区分を任意設定。曜日・時限数は可変、通常/短縮/午前/土曜/特別/考査等の時程を独立定義。時間割は適用開始・終了日を持つ版管理とし、A/B週は必要に応じて追加。時間割の版が重複する場合は確認して解決。
- 行事の効果は「表示のみ」「全休」「対象学年/時限の休講」「別曜日時間割」「時程変更」「考査」「個別変更」。予定タイトルのみで自動確定しない。初回はプレビュー承認、明示設定したルールだけ自動候補を作る。同日に競合する変更は要確認。
- 日別変更は元情報、適用範囲、理由を記録。振替は元の授業と移動先を紐付けて重複計上を防ぐ。過去の確定実績は変更の提案のみ、訂正は明示操作。
- Googleイベントは終日・複数日・繰り返し・タイムゾーンを正しく扱う。同日複数行事を保持。同期によるイベント更新と授業変更の確定を分離。

## 5. 授業計上
授業単位の安定ID、日付、時限、グループ、科目、種別、状態、元の時間割版、変更履歴を管理。
計算順序：年度範囲 → 有効な時間割 → 承認済み行事/曜日変更 → 時程 → 個別例外・振替 → 確定実績の保全。
予定、実施推定（終了時刻経過）、実施確定、取消、振替、自習/代講、考査、未確認を区別。通常は終了時刻で推定し一括確定を可能にする。簡易計上モードは推定を明示。
- 集計の軸：年度/学期/考査間/任意日付範囲/基準日、学年・科目・授業グループ。確定数・推定数・残予定数・合計見込みを別表示。欠課/考査等の計上可否は明示設定、変更前後の差を確認。
- 同科目のクラス間の実施回数差・将来見込み、授業日一覧、次回授業の回数表示。回数と分数は別指標。時程変更で回数を無条件に減算しない。
- 出席要件は学校規定に合わせて割合・等号・端数処理・対象授業を設定。欠席可能数は参考情報で、自動的に履修不成立を確定しない。

## 6. Excel互換・移行
既存の年間予定、時間割、実施授業、計上、授業日一覧、名列、進度記入用紙を概念上の移行対象とする。具体的な列・シート名・数式・基準値は実装時に原本を許可済みのローカル環境で検証し、機密を含まない合成fixtureを作る。原本や実データのGitHub保存は禁止。
- xlsx/CSV/ICS、クリップボードの表形式、直接入力に対応する方針。取り込み前に列マッピング、日付/時刻、同日複数予定、重複、未知クラス・不明式・外部参照を確認。Excelの保存済み計算値は未更新の可能性を明示し、アプリの再計算と照合する。
- マクロ実行・外部参照取得なし。元ファイルは変更しない。プレビュー、差分、確認、一括反映、取消、同じファイルの再取り込みによる重複防止。取り込み履歴に必要最小限の識別情報を保存。
- 出力：授業数、日別実施授業、授業日一覧、進度用紙、週間予定、任意の出欠表をA4印刷・PDF・Excelへ。初期は簡素な書式で可。正式な学校帳票との一致は別途確認。

## 7. データモデル（論理設計）
SQLiteを候補。年度、学期/考査期間、学年、クラス、科目、授業グループ（複数クラス可）、時間割版、時間割枠、時程/時限、イベント/取得元、行事効果、日別例外、授業インスタンス、実績訂正、進度メモ、ローカルタスク、設定、インポート履歴、任意の名列/出欠。年度・IDで分離。イベント外部IDと同期カーソルを保持。DB更新はトランザクション、スキーマ版を記録。
授業計上エンジンは純粋なローカル処理としてUIと分離。Googleアダプタは取得情報だけを返す。タスクは期限、完了、優先度、メモ、任意の授業紐付け。バックアップはローカル手動/任意定期、復元前に検証し現データを保全。認証トークンをバックアップに含めない。

## 8. 技術候補・制約
第一候補Tauri + ローカル同梱HTML/CSS/JS + SQLite、第二候補C#/WPF。既存OSSのウィンドウ固定やCalendar連携の再利用はライセンス・コード・依存確認後。採用技術は未確定。WebView2・管理者権限なし実行・校務PCのアプリ許可を試作で検証する。Windowsを対象とし、Web公開は今回の範囲外。
軽量性：待機CPUほぼ0%、総メモリ150MB以内を努力目標（未測定）。時計以外はデータ変更駆動、集計を毎秒再計算しない。外部フォントやリモートHTMLをロードしない。

## 9. 受入基準
合成Excelで取り込み・集計一致、同日複数行事、考査計上切替、振替の一回計上、短縮時程、版変更と過去実績維持、期間境界、再取り込み重複なし、バックアップ復元を確認。原本との比較はローカルで別途行う。
オフライン起動・保存・再起動、全ローカル操作で外向き通信なし、Google有効時のCalendar/OAuth以外の通信なし（実際のネットワーク観測）、同期失敗時のキャッシュ、名前データを含まないログ・公開物、常駐と終了・画面可読性をWindows実機で検証。
現時点は設計のみ。実装・CI・配布・校務PC実機動作は未検証。
